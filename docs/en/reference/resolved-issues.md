# Resolved Issues

Historical known issues that were reported against
[Implicit Behaviors, Edge Cases, and Known Issues](behaviors-and-limitations.md)
and are now covered by the current implementation and regression tests.

Two numbering series are in use:

- **K series** — the original numbering from when this list lived inside the
  behaviors-and-limitations page. Kept unchanged for historical continuity;
  no new K numbers are issued.
- **ODR series** — records from the defect registry (`defects.yml` at the
  repository root). Each ODR record carries the report date, affected
  versions, reproduction, disposition, and status, and every fixed record is
  backed by regression tests marked with its ID. See
  [Defect tracking](../contributor/defect-tracking.md) for the process.

New resolved issues are appended to the ODR table.

## ODR series

| # | Area | Resolution |
|---|---|---|
| ODR-0001 | Import wizard | Schema field names are no longer interpolated into INSERT columns: the wizard commit boundary validates and quotes every identifier (`operon.sql.quote_identifier()`), and a hostile schema raises `ValidationError` with the whole commit rolled back. |
| ODR-0002 | Database API | `insert_row()`/`upsert_rows()` and the read helpers `table_columns()`/`export_rows()`/`export_active_rows()` validate and quote every dynamic identifier; values remain parameter-bound, and keyword column names still work. |
| ODR-0003 | Table import | `apply_table_import()` revalidates the table against `IMPORTABLE_TABLES` and quotes all identifiers at the execution boundary; a tampered preview raises `ValidationError` and rolls back. |
| ODR-0004 | Remote mirrors | Upload verification now happens at the staging name inside `put`, before the final rename; a truncated or corrupted upload is removed with the staging bytes and never occupies the final remote path, so a later push retries instead of marking the location `CORRUPT`. |
| ODR-0005 | Release | The release preflight no longer returns early when `config/profiles/<profile>.yaml` is missing: `release` and decision-based `export` load and validate the named QC profile up front, so a typo fails with a validation error instead of publishing a zero-member release or an empty export bundle. |
| ODR-0006 | Release | A crash between the final rename and the `releases` insert no longer wedges the version: the retry recognizes the orphaned tree by its `provenance.json`, removes it, and rebuilds the release; any other occupant of the path still raises `FileExistsError`. |
| ODR-0007 | Export | The export `workflow_runs` row is now committed only after the workspace has been renamed to the final destination, with the command naming that destination; a recording failure removes the published tree, so a completed export whose destination does not exist can no longer be reported. |
| ODR-0008 | Export | Exports no longer use an existing empty destination as the workspace: every export stages in a hidden sibling directory, publishes by `rmdir` + atomic rename (failing safe if the destination gained content), and a failure only ever removes the staging tree — the caller's directory children are never deleted. |
| ODR-0009 | Ingest | An idempotent re-ingest no longer rewrites `files.status` unconditionally: a `STANDARDIZED` file keeps its status, and any real transition goes through `set_file_status` with its `changes` audit row. |
| ODR-0010 | Standardize | `standardize` no longer writes `STANDARDIZED` directly: the file status goes through `set_file_status` and the entity transition through `set_state`, both audited in `changes`; illegal transitions (for example re-standardizing a `RELEASED` entity) are rejected, and `CHECKSUM_FAILED` gained a legal recovery edge to `STANDARDIZED` for re-verified bytes. |
| ODR-0011 | QC / decisions | Re-running `qc` or `evaluate` no longer demotes `ACCEPTED`/`RELEASED` (or `REVIEW`/`REJECTED`) entities: the batch state writes go through `set_state_guarded`, which still records fresh QC evidence and decision rows but leaves the lifecycle state to an explicit `curate` or forced `set-state`. |
| ODR-0012 | Database | The derived-view rebuild on writable open now runs in a single immediate transaction (plain `execute`, because `executescript` would implicitly commit), so two processes can no longer collide between another connection's DROP and CREATE with `view ... already exists`. |
| ODR-0013 | Files / QC | Directory artifacts are now verified with the same deterministic tree hash used at ingest: `verify_local_file_identity` branches on the manifest format, a file↔directory type flip reports missing, and the stat-fingerprint cache is bypassed for directories (a directory's own mtime changes on any member touch). Built-in QC's checksum stage and `fanout` source verification now pass for intact directory trees. |
| ODR-0014 | TimeTree | Snapshot loading and calibration inputs now fail with `ValidationError` instead of bare exceptions: a missing/malformed/incomplete `snapshot.json`, an unreadable raw payload, non-numeric taxon IDs in the taxa/constraints tables, and an unreadable or malformed dating tree all report a contextual `error:` message (exit 2) rather than a traceback. |
| ODR-0015 | Shutdown | Interrupt-cleanup sites now call `shutdown.cleanup_completed()` once their bookkeeping is finalized, re-arming graceful handling: a signal arriving after cleanup (batch unwinding, exit-130 reporting) raises a fresh `ShutdownRequested` instead of force-exiting a process with nothing left to clean. The `os._exit(128+signum)` escape hatch remains for a second signal while cleanup is genuinely still running. |
| ODR-0016 | Analysis tools | The tool-version and database-identity caches are now TTL-bound (300 s) instead of process-lifetime: a batch still pays for one probe, but a long-lived process (the TUI) re-probes after expiry, so an in-place tool upgrade or a reference database replaced at the same path is noticed instead of planning with a stale identity. |
| ODR-0017 | Tests | The version-source test no longer races a concurrent sdist build: it re-reads `operon.__version__` via `importlib.reload()` while holding the machine-wide sdist build lock, so an xdist worker that imported `operon` during a sibling worker's in-place `OperonDBS.egg-info` rewrite cannot freeze a stale or missing version into the assertion. |
| ODR-0018 | Analysis tools | A cancellation raised by the analysis `progress_callback` on the Slurm-array path (the TUI's `AnalysisCancelled`) is no longer swallowed as per-file failures: callback exceptions now abort the batch — tasks that already wrote their exit-code file finalize as completed/failed exactly like the executor-interrupt path, every remaining plan is marked `interrupted`, and the original exception propagates to the caller. KeyboardInterrupt subclasses keep the existing outer interrupt path. |
| ODR-0019 | TUI | Filter rows no longer push their controls outside the box: every panel and modal filter row (`jobs-filters`, `hits-filters`, `hits-filters-2`, `hits-export`) got width rules — flexible search inputs take `1fr`, narrow selects and limit fields get fixed widths. A regression test mounts the affected screens and modals and asserts each control sits fully inside its row and is at least 8 columns wide. |
| ODR-0020 | TUI | The analysis-jobs dialog no longer collapses its table to a single row and overlaps its panes: it uses a fixed tall box (`#modal-box.jobs`, 80%) with a two-pane body — the table takes `1fr` and scrolls internally, the detail moves to a right-hand column. A regression test asserts the panes stay inside the box, do not overlap each other and keep a usable size. |
| ODR-0021 | Tests | A copied project no longer inherits the read-only state of the database it came from: `tests/helpers.copy_project_tree()` drops every `*.sqlite-shm` (SQLite rebuilds the shared-memory index from the log on the next open) and restores write permission on the copied database, log and journal files. `test_data_layer_never_writes()` now works on a private copy of the demo project instead of the shared module fixture, and a regression test asserts a copied project opens for writing after a read-only session. |
| ODR-0022 | TUI | A worker result can no longer land after its modal was dismissed: `operon/tui/screens/common.py` gained `WorkerResults`, whose `post_to_ui()` hands a result to the UI thread and `apply_from_worker()` drops it when the widget is gone. `WriteModal` and `Panel` inherit it, as do `AnalysisJobsModal`, `RunDetailScreen`, `SequenceLabelsModal`, `EnvironmentsModal`, `AnalysisHitsModal` and `ImportWizardScreen`, and every worker call site in `operon/tui/screens` now goes through `post_to_ui()` — which also replaced the hand-rolled `is_running`/`RuntimeError` blocks. The regression test pins the guard and its precondition (the unguarded call still raises); the race itself is timing-dependent. |
| ODR-0023 | TUI | The config editors no longer read a form whose deferred rows have not mounted: `MountTracked` (`operon/tui/screens/common.py`) is a container that fills itself later and reports `mounts_settled`, every editor row (`RuleRow`, `ConditionRow`, `ConditionEditor`, `BestByRow`, `SourceRow`, `ClassificationRuleRow`) is a `ComposedRows` that latches `form_ready` in its own `on_mount`, and `ConfigPanel._form_mounting()` answers from both signals — a save landing while the form is still building is refused with `FORM_MOUNTING_MESSAGE` instead of walking a half-built tree. `FittingSelect` shields Textual's own mount-time lookups by retrying `_setup_options_renderables`/`_init_selected_option` a turn at a time. The tests wait through `_await_form_ready`/`_await_rows` before reading a form directly, `_click` tolerates `OutOfBounds` and waits out the lingering `-active` press effect (ODR-0024), and two regression tests pin the save refusal and the row latch. A late-binding bug found on the way (`SourceRow.on_mount` sharing one `view` between two lambdas) went with it. |
| ODR-0024 | Tests | A second click on a button is no longer swallowed by the press effect the button still shows: `tests/unit/test_tui_config.py::_click` waits for the `-active` effect to clear before clicking again — the same step `test_tui_derived_ops.py::_click` has carried since the derived-artifact dialogs — and the recipe test waits for the outcomes it expects (the inline conflict error, then the modal) instead of a single `pilot.pause()`. The test carries `@pytest.mark.bug("ODR-0024")`. |
| ODR-0025 | CI | The publish workflow no longer builds the pre-split documentation directory: it builds `docs/en` and `docs/zh` exactly like the CI docs job, and `tests/unit/test_docs_projects.py` gained a guard that reads the workflow files (both the inline `run:` and the block form) and fails when a `sphinx-build` line does not name both language trees. |
| ODR-0026 | TUI | A condition's operator no longer composes as blank when a `Select` could not finish mounting: `FittingSelect` adopts the value it was built with before deferring (`_adopt_value_before_overlay`) and publishes `options_ready`, which `ConfigPanel._form_mounting` now requires of every `Select` in the form, so a reader waits instead of composing a blank operator. `BestByRow` parses rank values and defaults through `actions.coerce_scalar`, keeping whole numbers whole. |
| ODR-0027 | Tests | Two config-screen tests no longer read the UI a message-loop turn early: neither wait is a fixed number of `pilot.pause()` cycles any more — the scroll test waits through `_await_form_ready` and then for the editor's own growth, and the notification assertions go through a new `_await_notification` helper. Applied to every site of that shape in the file (six notification assertions), because the ones that happened to pass are the ones the next slow run picks. |
| ODR-0029 | Tests | Run-detail tests no longer treat an empty worker set as completed screen loading: every read of `#run-detail` waits for the content it asserts instead. `test_tui_writes.py` gained `_detail_text()`/`_await_detail_text()`, its two run-external sites read the detail text only once their marker is there, and the `test_tui.py` runs-table site uses its own copy of the pair. The window is also guarded rather than only fixed: `test_no_tui_test_reads_run_detail_straight_after_settling` scans the test modules for a raw `_static_text(...query_one("#run-detail")...)` assignment and fails on one, and `test_run_detail_read_waits_for_the_loaded_content` holds the screen load back so the old gate passes while the placeholder is still up. |
| ODR-0030 | TUI | Old editor rows no longer satisfy readiness during a deferred form replacement: `MountTracked` retires the generation it is replacing before mounting the next one and stamps each replacement with a generation token, so a replacement superseded while its removal is in flight drops its mount instead of adding a second generation. `mounts_settled` reports false until the awaited replacement has landed (an `_EMPTIED` sentinel keeps a populated-to-empty replacement in that waiting state) and `_replacing()` keeps readiness false while a previous generation is still in the tree. The regression test drives two rebuilds inside one turn and then saves, asserting one generation of rows and a document equal to the file's. |
| ODR-0031 | TUI | Detail panes no longer apply a worker result that no longer matches the selection: `WorkerResults` stamps every request with a key that the panel hands to the worker (`post_to_ui(..., key=...)` on the thread side, `apply_from_worker(..., key=...)` in the panel), so a payload arriving after a newer request was stamped is dropped. A result without a key and a widget that never stamped one are both treated as current, so the mechanism is inert for workers that do not opt in: `Panel.begin_request()` and `is_current_result()` are the two halves, `FilesPanel`/`EntitiesPanel` stamp the `file_id` or the entity key, `CoveragePanel` the report id, and `PublishPanel` the release profile and the export filter tuple. |
| ODR-0032 | TUI | A dropped initial panel render no longer leaves the app on the splash screen: `Panel._apply` still drops a result whose widgets are gone, but a dropped result no longer returns before the app is told the panel's first load is over — the initial-load state latches either way, so a live render failure is reported instead of parking the splash. `OperonApp._finish_startup` stops waiting for panels that never report at all: after `startup_deadline` seconds it shows what did load, logs the panels that did not, pops the splash and notifies the user that `r` retries. The deadline is covered by stepping the app clock (a frozen clock cannot show elapsed time), and the panel-level test parametrises both drop shapes, `MountError` and `NoMatches`. |
| ODR-0033 | Tests | Environment-capture tests no longer assert a raw path that capture redacts under `$HOME`: the three assertions compare against the capture's own form of the path through a new `_captured()` helper that applies `environment._redact_home` with `environment._local_home()` to the expected value, so they hold wherever the scratch directory lives; a run whose `TMPDIR` is inside `$HOME` is now a condition the matrix exercises instead of one it trips on. The three tests carry `@pytest.mark.bug("ODR-0033")`. |
| ODR-0034 | TUI | The classification editor's nesting limit is no longer enforced by branches no caller can reach: the depth parameter is gone and `_condition_within_depth(condition)` returns `False` for a group inside a group, a `not:` of a group, a non-list `any:` group and a non-dict condition — exactly the shapes `classification_form_supported` refuses. The `_rebuild` leaf fallback stays as the editor's own last line of defence and now says so in a comment. Pinned by `test_classification_form_refuses_what_it_cannot_represent`, whose cases name every refused shape and the reason the read-only note shows. |
| ODR-0035 | TUI | The classification editor no longer raises while a mode change replaces its body: `editor_document()` asks the body's own `MountTracked.mounts_settled` first — the readiness answer ODR-0023 introduced — and composes `ConditionEditor._seeded_document`, recorded by `_rebuild` before it replaces the body, while the rows are not there yet. Both modes answer with the seeded condition instead of raising (leaf/`not:`) or reporting an empty group (`any:`), so a save landing in the window keeps the condition the user was editing. Pinned by a test that hooks the body's own mount so the read happens exactly inside the window instead of when a poll happens to land there. |
| ODR-0036 | TUI | A composition that lands while a nested condition row is being removed no longer reads a row with no inputs: `editor_document()` composes only rows whose `.condition-field` is in the tree (`ConditionEditor._composable_rows`) and falls back to `_seeded_document` when the leaf/`not:` body has no such row, so the `any:` branch reports the rows that remain and the leaf branches keep the condition instead of raising. Pinned by a test that reads every turn from the ✕ press until the row is gone. |
| ODR-0037 | Tests | A shutdown test no longer reads the grandchild pid file before the shell has written the pid: `_grandchild_pid()` polls until the file's content parses, with the same five-second budget, at both read sites — the pre-interrupt wait keeps its tolerance (it may proceed without a pid) while the post-run read is strict. The test carries `@pytest.mark.bug("ODR-0037")`. |
| ODR-0038 | TUI | A `Select`'s own `on_mount` no longer runs unguarded beside the guarded override: `FittingSelect` overrides the two methods Textual's handler calls through the instance (`_setup_options_renderables` and `_init_selected_option`) and absorbs the overlay `NoMatches` there, so the base handler cannot raise. Readiness can no longer be inferred from that exception, so `_on_mount` and the retry ask the tree instead (`_overlay_present`) before latching `options_ready` — the ODR-0023/ODR-0026 contract is unchanged for readers. |
| ODR-0039 | TUI | An exhausted `Select` mount retry no longer leaves `options_ready` `False` for good with the form gate then waiting forever: `FittingSelect` gained `options_gave_up` (a second signal beside `options_ready`) and logs one warning naming the control when the retry budget runs out. `ConfigPanel` answers a blocked save through `_blocked_save_message`, which names the stalled controls and points at a profile reload once any of them gave up, and keeps the still-loading wording otherwise. |
| ODR-0040 | QC / reports | Text cells that a spreadsheet would execute are escaped with a leading apostrophe — a value beginning with `=`, `+`, `-`, `@`, TAB or CR. This covers `sequence_qc.tsv` from both alignment backends (byte parity kept) and every `write_tsv` consumer (release and export manifests, report TSVs, TimeTree candidate tables). Non-string cells keep their exact bytes, an already-escaped value is not escaped twice, and provenance hashes are computed over the escaped bytes, so re-reading a release stays consistent. |
| ODR-0041 | TUI | The Config screen's History button no longer gates on the QC-only profile field: `_open_profile_history()` resolves the profile name through `_active_profile_name()`, which answers with the classification editor's own name while that editor is on display and with `current_profile` otherwise, so History opens the snapshot history of the profile the user is actually editing. Pinned by a test that clicks `#classification-history` from a fresh screen (no qc profile ever selected) and asserts the modal title names the classification profile — and that a stale qc selection does not leak into it. |
| ODR-0044 | Export / reports | `write_tsv` now decides cell quoting itself instead of delegating to `csv`: a cell containing TAB, CR, LF or `"` is quoted with its inner quotes doubled, everything else is written verbatim. CPython 3.11 changed the csv rule for CR/LF cells, so on 3.10 the same row produced different bytes and artifacts hashed for provenance (release manifests, export identities) depended on the interpreter. The bytes are now identical on 3.10–3.15 and unchanged from the previous 3.11+ output. |
| ODR-0045 | TUI | A panel load is stamped with a generation: `reload()` hands the worker the generation stamped on the UI thread, and a payload a newer load superseded is dropped instead of rendered. Before, a read already inside a thread could land after a newer one and restore the rows a just-typed filter had removed — the macOS/Python 3.15 CI shape, where the entity filter never latched. |

## K series (historical)

| # | Area | Resolution |
|---|---|---|
| K1 | Decisions | Re-evaluation appends an automatic row while carrying the current `curated_*` fields forward. The CLI previews all affected curated entities and asks once before any write; non-interactive runs require `--yes`. |
| K2 | QC state | Each file has an aggregate QC status. An entity takes the worst sibling status (`QC_FAILED` > `QC_RUNNING` > `QC_COMPLETE`), and `operon qc` lists every file status. |
| K3 | Standardize | Batch standardization returns exit code 1 when any file fails. |
| K4 | Release | Releases are built in a hidden staging directory and published atomically. Failed builds remove staging output; a database commit failure also removes the published tree. |
| K5 | Release | Release membership, audited `RELEASED` transitions, and the release row commit in one transaction, so a partial state update is rolled back. |
| K6 | Export | Exports are built in a temporary sibling and renamed only after all artifacts are complete; failures clean the temporary tree or restore an existing empty destination. |
| K7 | Table import | Updating existing metadata preserves its lifecycle state and audit history. Release preflight treats changes after evaluation as stale and requires a fresh QC/evaluation. |
| K8 | Ingest (`move`) | Move mode copies and verifies the archive, registers it, and removes the source last. Copy, checksum, or transaction failures leave the source recoverable. |
| K9 | Utilities | Empty tables render one header and separator, without a duplicate data row. |
| K10 | Import wizard | The annotation prompt defaults to the draft's current presence (`yes` only when an annotation is already selected). |
| K11 | Classification | A missing field never satisfies a condition in any form — including inside a `not:` negation and as a disjunct of an `any:` group; `between` on non-numeric operands raises a validation error naming the field and value instead of a bare `ValueError`. |
| K12 | Classification | `classify-sequences` no longer hides what it ignores: superseded (non-latest) completed jobs are counted as `ignored_completed_jobs` and surfaced with a warning, and files skipped for being absent from the `sequences` registry are counted explicitly. |
| K13 | Fan-out | `fanout --dry-run` now performs the full preflight — source checksum and registry freshness, unit identity computation, and conflict/occupancy checks — and raises `ConflictError` exactly as a real run would, while still writing no files and opening no run row; each planned unit is annotated `would_create`/`would_reuse`. Unit seqids are also canonicalized into sorted order before the FASTA is generated, so reordering the assignment TSV no longer changes unit bytes. |
| K14 | Fan-out | An interrupt (Ctrl+C) now finishes the fan-out workflow run as `interrupted` with exit code 130 instead of leaving the row `running`; targets created by the run are still removed. |
| K15 | Recipes | `file_role_prefix` matches at a `:` boundary: `sub` selects the exact role `sub` and every `sub:*`, and no longer captures `sub2:*`. |
| K16 | Execution backends | A signal-killed Slurm job is no longer recorded as success: the `sacct` fallback folds a nonzero signal component of `exit:signal` into a shell-style exit code (an OOM kill's `0:9` becomes 137) and records the signal as `slurm_exit_signal` in the run details, and the exit-code/accounting retries are raised from 5 attempts × 1 s to 10 × 2 s (`_SLURM_EXIT_CODE_RETRIES`/`_SLURM_EXIT_CODE_RETRY_SECONDS`). |
| K17 | Execution backends | The SSH backend no longer deletes remote outputs before a run: an existing remote output is first renamed to a `<path>.operon-prev-<uuid>` backup, the backup is dropped once the run succeeds and the new output verifies, and a failed or interrupted run best-effort restores the backup in place, so a failure no longer destroys the previous remote output. |
| K18 | External analyses | The stale-`RUNNING` sweep is now scoped to the current analysis: a non-dry `analyze` marks only that analysis's `RUNNING` rows `interrupted`, so a concurrent run of a different analysis no longer loses its live jobs (`tools.py`, `_sweep_stale_running_jobs`). |
